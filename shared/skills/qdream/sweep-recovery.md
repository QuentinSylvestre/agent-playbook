# qdream sweep — crash recovery (Phase 1)

Part of the `/qdream` skill: `SKILL.md` in this directory loads this file only when `memory/.dream-journal.jsonl` is non-empty, during a full sweep (its phase index). The Rules and destructive-path invariants in `SKILL.md` apply here, including its Single-flight invariant (`SKILL.md § Destructive-path invariants`): when the user indicates another sweep may be in flight, stop rather than recover.

### Phase 1 — Orient: crash recovery

   **Crash-recovery journal** `[ORI-RECOVER]` (full-sweep-only). If `memory/.dream-journal.jsonl` exists and is non-empty (the crash signal — a prior sweep was interrupted after a destructive mutation but before `§ APP-STATE` completed): recover from the journal.

   - **Validate the journal first**: run `<python> shared/skills/qdream/scripts/verify-dream-journal.py` before consuming any record. A torn final line (WARN, exit 0) is the expected crash artifact — proceed. Any other non-zero exit (2: the validator did not run) also halts recovery. A FAIL (interior parse error, or a record that parses but violates the grammar — corruption beyond a torn suffix) means the journal is untrustworthy: surface the FAIL output and the raw journal to the user and halt recovery, rather than seeding the working map or emitting landed reports from a malformed record (fail-safe toward keep — an unvalidated corrupt journal must not drive autonomous state).

   Then, for each record in the journal:

   - **Derive the target file** from the record's fully-qualified path-key: for `project memory (<path-key>) § <heading>`, the file is the memory-class location `shared/skills/qdream/memory-rules.md § Resolution contract` returns for `<path-key>` — the store's `memory/MEMORY.md` (never an in-workspace copy, which the sweep never writes), and deriving the in-workspace path reads a file the sweep did not write, so recovery silently under-recovers; for `user memory § <heading>`, the files are the config-repo's `memory/MEMORY.md` and every `memory/topics/*.md`, the heading present when any of them holds it (`[improvement_signal]` entries live in `memory/topics/improvement-signals.md`). Read those files (a targeted memory-file read, Rule-7-safe — no dependence on Phase 2 project analysis or `§ ORI-READMEM`).
   - **Apply the landed truth table.** This is its one definition; `shared/skills/qdream/memory-rules.md § Crash-recovery journal` defines the journal's format and points here. *Surface it* below means: hold a report line, which becomes a line in `orient.json`'s `recover_lines` (see *Hold the results*) and from there the Report's `Recovery` line. (regression fixtures: transition-fixtures.md FIX-RECOVER-*)
     - *Rename* `{"rename":[A,B]}`:
       - `A` absent and `B` present → **landed**: hold the `A→B` pair for this sweep's working-map seed (below).
       - `A` present, whatever `B`'s state → **didn't land, or ambiguous**: no-op, and surface it.
       - `A` absent and `B` absent → no-op, and surface it.
     - *Remove* `{"remove":[T,class]}`:
       - `T` absent and its file readable → **landed**: hold the Rule-6 report line (it goes to `recover_lines`, see *Hold the results*); the journal record outlives this step, so a second crash cannot lose it.
       - A `user memory § H` record of class `pruned` with `H` absent from `memory/MEMORY.md` and present in a topic file → **landed**, as a deleted duplicate `MEMORY.md` copy: the entry survives, so report it as moved, never as a deletion. This case is checked before the next one. The opposite duplicate case, a deleted topic-file copy while the `MEMORY.md` copy remains, cannot be told apart from the record alone: it reads "didn't land" (the fail-safe direction, a surfaced no-op).
       - `T` present, for user memory in any of `memory/MEMORY.md` and the `memory/topics/*.md` files, and not the `Move` case above → **didn't land**: no-op, and surface it. Every remove record matches exactly one row, and a removal that did not land never reads "landed" (for example an `expired_signal` removal of an entry in `memory/topics/improvement-signals.md` that is still there).
       - `T`'s file unreadable or absent (for example a project directory not on this machine) → **indeterminate**: no-op, and surface it; never a landed report. A file the sweep cannot read is no evidence of absence (the `confirmed-absent` versus `indeterminate` distinction, `shared/skills/qdream/memory-rules.md § The reconciliation pass — three steps, and the order is normative`, Step 2).
   - **Report, never restore.** Recovery reports that a deletion happened. It does not re-run the decision behind it and does not restore content: the journal holds the heading and the removal class, not the entry body.
   - **Hold the results until the work folder exists.** This step runs before `§ ORI-DISCOVER` creates the work folder (`sweep-handoff.md § Orient order`, step 3), so it holds its landed rename pairs and its report lines in context, and writes nothing. Right after `dirty`, the orchestrator writes the landed pairs to `handoff/working-map-seed.json` (an empty `pairs` list when none landed), which `dream-write.py memedit` loads as this sweep's working map on its first run, and the report lines into `orient.json`'s `recover_lines`, which the Report carries. On a Resume of a paused sweep this step is skipped: the paused sweep's seed and working map already hold its pairs. On a Discard of a paused sweep it runs after `clean`.
   - **Do not clear the journal** at this step (clear-on-success happens only at `§ APP-STATE`).
   - **Idempotent**: re-running recovery on the same journal produces the same outcome (ground-truth re-verified each time).
   - **Fail-safe toward keep**: on ambiguity, surface and leave the entry alone.
   - **Reused-heading residual**: a `B`-present check can match a reused heading of unrelated content. The re-point onto it is the residual the reconciliation pass's resolve step already accepts (`shared/skills/qdream/memory-rules.md § The reconciliation pass — three steps, and the order is normative`, Step 2, *Accepted residual*; over-retention at worst; node removal stays user-gated), not a stronger guarantee.

   If the journal is empty or absent, skip recovery (no crash signal). `§ ORI-RECOVER` is the journal's consumer per `shared/AGENTS.md § Structure Requires a Consumer` (type-3: consolidation-sweep consumer — reads every full sweep, acts conditionally on a non-empty journal).
