## Authoring reference (shared/, deployed)

- `shared/AUTHORING.md` — the **canonical owner** of the playbook's own authoring conventions, deployed alongside `AGENTS.md`. Two sections, both of which `shared/AGENTS.md` carries only in summary-plus-pointer form:
  - `§ SKILL.md Authoring` — full rules and rationale: quoted `argument-hint` values, repo-relative cross-file paths, curly-brace `{token}` markers in verbatim sub-agent briefs, a named first action for behavior-overriding skills, an explicit when-NOT-to-use note, a named fallback for closed-set choices, skills written as deviations from default behaviour rather than tutorials
  - `§ Structure Requires a Consumer` — full rule and its relation to the Leanness review standard
- Route an authoring-convention change here, not to the `AGENTS.md` summary. Landing it in the summary alone leaves the canonical text stale, and the summary is what a search for "SKILL.md authoring" hits first.

Manual-only via `disable-model-invocation`. Route reader-comprehension, code-explanation, walkthrough, diagram-generation, and onboarding-a-change concepts here; change *evaluation* concepts belong to `shared/skills/qreview/SKILL.md`
- `shared/skills/qexplain/scripts/validate-explanation.py` — deterministic validator for a generated explanation artifact (stdlib-only Python), eleven checks: `document-shape`, `title-present`, `remote-assets-pinned`, `no-module-scripts`, `no-runtime-fetch`, `code-whitespace`, `anchors-resolve`, `tabs-wired`, `parts-wired`, `verified-section`, `no-emoji`. Owns the known-CDN host list and checks the attribute contracts the template emits: `data-part` / `id="part-<key>"` for parts, `data-view` / `id="view-<key>"` for map tabs
- `shared/skills/qexplain/assets/template.html` — the fixed artifact page: part bar, map tabs and tours, theme toggle, hash routing, Mermaid note fix, and the whole diff-review UI. The agent never rewrites it; it supplies content files instead
- `shared/skills/qexplain/scripts/build-explanation.py` — fills the template from the agent's content files (narrative and summary fragments, `maps.json`, `rationales.json`), captures one or several repos' diffs as UTF-8, leaves out secret-bearing files, stops on credential-shaped text, warns on files without a rationale, then runs the validator (stdlib-only Python)
- `shared/skills/qexplain/scripts/measure-change.py` — prints a change's size tier from its lines to read, its plans, the files left out, credential-shaped matches by path and line, and whether to propose a split, before anything is read (stdlib-only Python). `scripts/qexplain_diff.py` holds the diff helpers it shares with the build
- `shared/skills/qexplain/scripts/visual-check.js` — Playwright check of a built artifact: maps drawn, every tour step, hash routing, Mermaid notes, theme, every diff-review control, phone width; prints OK/BAD lines and saves screenshots. Its header comment is the manual checklist for a Playwright MCP

## New skill landing zone

When a concept is substantial enough to warrant its own skill, recommend: "New skill: `shared/skills/<name>/SKILL.md`" with a one-line description of what it would do. Use `providers/kiro/skills/<name>/` only for Kiro-specific capabilities.
