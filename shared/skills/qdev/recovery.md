# /qdev — interruption and recovery reference

<!-- Read on demand from shared/skills/qdev/SKILL.md § Interruption and recovery reference, when a row below may apply. -->

| Scenario | How to detect | What to do |
|---|---|---|
| Session start, before any commit (orphaned working tree) | Run `git status --short` before starting a phase. Uncommitted or untracked changes touch files in a pending phase's file scope — the atomicity check below can't see this, since nothing was committed. | Treat as candidate orphaned work from an interrupted prior session: never assume a clean start, never silently commit, never assume the phase is done because its edits are present. Verify each change against the phase's exit criteria, then choose: **Treat as incomplete** (default — resume from the first unmet exit criterion), **Adopt as-is** (route through the normal Step 5 review, repairing incomplete edits first), **Discard and re-run the phase** from a clean tree, or **Stop** (leave the tree untouched, hand back to the user). If none fits, say so and ask — do not proceed on an invented framing. |
| Mid-execution, between phases (dirty tree) | After every sub-agent return — implementation, review, QA, or doc-impact, not only implementation — run `git status --short`. Modifications exist to files NOT in the current phase's file scope. | STOP and surface the file list to the user. Never discard (`git checkout`), stage, or assume the changes are noise — they may be another agent's in-progress work or a legitimate concurrent edit. Reinforces `shared/AGENTS.md § Commit Safety` ("never unstage, discard, or modify files you did not create or edit in the current task"). |
| After the code commit, before the plan commit (atomicity reconciliation) | qvalidate's `commit-pairing` check (`--check-commits`; see `shared/skills/qvalidate/SKILL.md`) flags a `feat(<plan-slug>): ... phase N` commit with no matching `docs(<plan-slug>): ...` commit. | Treat the dangling commit as Phase N's implementation, apply the skipped Step 7 plan updates, and emit the paired plan commit referencing the existing SHA — the sanctioned response to `commit-pairing`'s FAIL here (atomicity carve-out in `shared/skills/qvalidate/SKILL.md § Failure semantics`). Fall back to the halt-and-user-decide default only if reconciliation can't proceed cleanly (ambiguous phase, or the results-based row below applies). Inline plans (no project file) are exempt — `commit-pairing` does not apply. |
| Reconciling a results-based phase (measurement/spike caveat) | The dangling commit (row above) belongs to a phase whose exit criteria are results-based — a benchmark with a gating metric, a spike answering a question, any phase ending in a user decision gate. | Verify the commit's **output** against the exit criteria — run or inspect it — before ticking them. Code-present does not mean phase-done: a harness can be committed and pass its own tests without yet producing the gating measurement, so the verification target is the produced result, not the presence of the code. |
| Mid-phase, sub-agent interrupted before committing (in-session) | An implementation or auto-fix sub-agent stops mid-session (harness exit, API error) after editing but before committing. | If the interruption is resumable, resume the same sub-agent (its context is intact). Otherwise verify the recovered edits against the phase/fix spec and run the phase's verification commands; if complete and green, the orchestrator commits them with an authorship note (sub-agent-authored, orchestrator-committed after interruption) and proceeds to the normal review step; if incomplete, re-spawn with the recovered working-tree state described in the brief. |
| Mid-phase, sub-agent committed but never returned (in-session) | The phase has a new code commit from the sub-agent, but its return never arrived (quota, harness exit). | Verify the commit's output, as in the results-based row: read its diff against the phase spec and run the phase's verification commands. If complete and green, write the plan notes from the diff with an authorship note (sub-agent-committed; notes orchestrator-written after a lost return) and proceed to the normal review step. If incomplete, re-spawn with that commit named in the brief as the starting point. |

Cited from `SKILL.md` Step 1 (rows 1-2) and Step 4 (rows 3-6).
