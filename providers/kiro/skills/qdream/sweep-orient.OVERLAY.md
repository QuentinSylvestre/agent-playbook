## Orient discipline (qdream)

These reinforce `§ ORI-DISCOVER`, `§ ORI-ROUTE` and the stamping in `shared/skills/qdream/sweep-decide-apply.md § APP-STATE`; appended to the deployed `sweep-orient.md`. Spelled out here because the kiro model must not hand-roll discovery, reuse a stale work folder, or stamp a project past sessions it never read. Full sweep only.

- **Run the manifest; do not discover by hand.** `dream-manifest.py manifest` is the only discovery and session-selection step. Do not glob session stores yourself, re-filter `sessions[]`, or add sessions the manifest did not list. If the script cannot run (no Python 3, exit 2 or 3), stop and report — do NOT fall back to reading session stores manually.
- **Exclude your own session.** kiro-cli 2.31.1 sets `KIRO_SESSION_ID` to your top-level session id (`sess_<uuid>`; `providers/kiro/steering/kiro-cli-local-data.md § Environment variables available to the agent`). When it is set and starts with `sess_`, pass it to the first `manifest` as `--exclude-session <that id>`, and do not ask the user. Only when it is unset (older v3 builds, `kiro-cli acp`) does the first `manifest` run without `--exclude-session`: your running session is `in_progress` and modified within 24 h, so the manifest should list it as `deferred`. At the confirm list, show the `deferred` sessions and ask the user which one is this running sweep. When the user names one, run `clean`, then rerun `manifest` with every earlier flag plus `--exclude-session <that id>`. When the user cannot tell, keep the manifest and say in the Report that the own session was not excluded. If your session is listed as `normal`, name it in the Report.
- **A paused sweep is checked before § ORI-RECOVER.** Follow `shared/skills/qdream/sweep-handoff.md § Orient order` exactly: a work folder holding `handoff/progress-*.json` is a paused sweep. Run `dream-sweep.py dirty --repo <config-repo>` (on a paused sweep it only re-validates the stored snapshot) and `drift --phase paused --snapshot-sha <sha>`. When either fails, or `sweep/drift-paused.json` has `incident` true, offer only `Stop` and say the folder and `sweep/backup/` are kept: never offer Discard then, because `clean` deletes the backup too. Otherwise offer `Resume / Discard / Stop`. A Discard lists the files the paused sweep wrote (from `sweep/hashes.json`) before `clean`. When the user says another sweep may be running, offer only `Stop` and run nothing.
- **Exit 5 means a leftover work folder: ask, never decide.** Present three choices — resume (the existing `manifest.json`, its own `snapshot_at`), discard (`clean`, then rerun `manifest`), stop. When the printed `snapshot_at` is `unknown`, `manifest.json` does not parse: offer only discard and stop. No answer, or any hint that another sweep is running, means stop. NEVER delete, empty, rename or write into the folder yourself; NEVER run `rm -rf` or `Remove-Item -Recurse` on it. Only the script's `clean` deletes it.
- **A rerun needs `clean` first.** Adding a path (`--add`) or reading a whole history (`--full`) at the confirm list means `clean`, then `manifest` with every earlier flag plus the new ones. Rerunning without `clean` exits 5 — that is not a leftover from another run.
- **Show errors, never drop them.** Every `errors[]` line, per project and top-level, goes on the confirm list verbatim. A project with errors stays on the list.
- **Hold the two values `dirty` prints.** Right after `manifest` exits 0, run `dream-sweep.py dirty --repo <config-repo>` and hold its `snapshot sha256` and `guard digest` for the whole sweep (`shared/skills/qdream/sweep-handoff.md § Orient order`).
- **Dispatch by the cadence, exactly** (`shared/skills/qdream/sweep-orient.md § ORI-DISPATCH`). Write `handoff/orient.json` with `dream-sweep.py orient` (never by hand; on kiro its `orchestrator_sessions` is `[]`), run `handoff check orient.json`, then `dream-sweep.py dispatch --confirmed orient.json --snapshot-sha <sha>`: the script builds the list by the rules below. Never build or edit the list by hand; check its summary against these rules. A session or a new plan → `all tasks`. Otherwise `memory_pass` `flagged` or `periodic` → `Tasks 4-5 only`, but first read the project's `errors[]`: an `unreadable memory file` line means report it and dispatch nothing. Otherwise → no agent. `cited_paths_missing`, `cited_slugs_missing`, `cited_path_changed`, `cited_commit_missing`, `stale_when_unknown` and `suspect` NEVER dispatch by themselves; `stale_when_fired` does, like `stale_after_passed` (`shared/skills/qdream/memory-rules.md § Suspect memory entries`). User memory: `periodic` → one dispatch per file; `flagged` with the `user_memory` block's `quiet_sweeps` at 4 or more → one dispatch per file too; `flagged` below 4 → one per file whose `file_flags` hold `stale_after_passed`, `stale_when_fired` or `governance_conflict_open`, never a file with none of those three.
- **Routing: recommend the orchestrator's own model for every role** (`task4`, `verifier`, and `drafter` when the sweep drafts governance proposals). Do not recommend a cheaper model on kiro-cli, and offer none. Phase agents are not a role: they run on your own model, launched through `subagent_kiro_default` (`SKILL.md`'s `## Phase agents and handoff files (kiro)`). Children run on the model the deployed `qdream_child` agent pins (the `model:` line of `~/.kiro/agents/qdream_child.md`), the same one `kiro_default` pins. A session cannot change it per call, so record that pinned model in `model_routing` for every role: it is the model the children ran on, whatever the user said. A user who asks for another model is told that it means editing that agent file and re-running setup.
- **Stamping is `snapshot_at`, and only for the stamp set `dream-sweep.py coverage` writes.** `coverage` runs at the end of Gather and writes `sweep/coverage.json`; `dream-write.py state apply` stamps exactly its projects. Never decide a stamp yourself, add a project to the set, or write the state file another way. `last_run` and every stamped `last_analyzed` are the manifest's `snapshot_at`, copied verbatim — NEVER the current clock, NEVER a composed timestamp. These are the rules `coverage` applies; check the Report against them. A project is stamped only when every agent serving it returned with `error` null and `project_accessible` true, and the id of every `normal` session handed to it is in its returned `sessions_read`. `notes` never block a stamp; `error` is only for a failed analysis. A project whose `errors[]` names a transcript or session the script could not read is NOT stamped, even when its dispatch was `Tasks 4-5 only` with an empty session list. A project whose listed sessions are all `deferred` was not read and is NOT stamped (reason `deferred-only`). A failed, skipped or truncated project keeps its old `last_analyzed`. A new project declined at the confirm list is NOT written to the state file at all — the next sweep offers it again. A new project dispatched but not stamped, or confirmed but given no agent (quiet), gets `new_project_baseline.since`, never `snapshot_at`; when `since` is null, it gets its earliest listed session's `first_activity` minus one second (`1970-01-01T00:00:00Z` when none has one). Stamp known projects under the manifest's `state_key` when it has one.
- **`clean` is the last act, and only the orchestrator runs it.** Run it only after `verify-dream-state` passed and the journal was cleared, and on Abort — except after a state-file or journal incident (`drift` reported `incident`): then keep the folder and `sweep/backup/`, and the next Orient offers the folder as a leftover. If `verify-dream-state` failed, do not clean. On exit 6, name the printed leftover path in the Report, do not retry and do not delete it yourself, and continue to the Report.
