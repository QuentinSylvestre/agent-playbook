## Insights extraction (qdream)

These elaborate the positive-signal / friction-narrative extraction added to § GAT-SESSIONS and the plan-efficiency signal added to § GAT-PLANS in `### Phase 2 — Gather` of `sweep-gather.md` (this overlay merges into it); spelled out here because the kiro model needs the exclusions and priority made explicit.

- **Satisfaction exclusions.** Exclude greetings, bare acknowledgments ("ok", "thanks"), and praise unrelated to the agent's output — count only evaluation that clearly refers to what the agent just produced ("thanks, that works" counts; a bare "thanks" does not).
- **Silence is not praise.** `likely_satisfied` (continuing without complaint) is an inference from absence, never equal-weighted with explicit praise, and counts only when the accepted choice was genuinely non-obvious. A "what's working" claim resting only on `likely_satisfied` signals is built out of silence — omit it.
- **Do NOT flatter the harness.** This is the one claim in the sweep the Cross-validation verifier never checks. Attribute to a specific skill or rule a specific signal supports, or say nothing — no quota, never pad the section.
- **Insights priority.** Under context pressure, sacrifice insights extraction before § GAT-SESSIONS's own friction analysis and pain-signal extraction — distinct from the shared brief's cross-task Priority weighting (Tasks 4-5 before 1-2).

## Dispatch and harvest (kiro)

These reinforce `### Phase 2 — Gather` in `sweep-gather.md` and the dispatch rule of `shared/skills/qdream/sweep-orient.md § ORI-DISPATCH`; spelled out here because the kiro model must neither skip a project the cadence dispatches nor dispatch one it skips, and must not fill a gap from its own reading.

- **You are the Gather phase agent: read the kiro phase-agent rules first.** Before your first step run `<python> <skill-dir>/scripts/dream-check.py extract --file <skill-dir>/SKILL.md --section "## Phase agents and handoff files (kiro)"` and follow it: children through `subagent_qdream_child` (never `subagent_kiro_default`), returns through `extract --kiro` (the inbox only as that section's fallback), never `wait`, never a question to the user.
- **The cadence decides, not the cost.** A confirmed project gets no agent only when `shared/skills/qdream/sweep-orient.md § ORI-DISPATCH` says so (no session, no new plan, no `flagged` or `periodic` pass). `sweep/dispatch.json` already holds that list: dispatch exactly its `agents`. NEVER skip a project it lists to save context, and NEVER dispatch a quiet project just to harvest its plans or re-check a missing path.
- **Render every brief with `dream-sweep.py brief --kind task4` and launch each child with the exact prompt line it printed.** The rendered brief carries the `{task_scope}` and each entry's flags and `suspect` value. Never write, retype, summarize or shorten a brief yourself. A suspect is never evidence of staleness: it only selects the entry for a full check, and a passing check re-dates it as `sweep`, NEVER over a `human:` actor: that `Verified` line stays untouched (`shared/skills/qdream/memory-rules.md § Suspect memory entries`). A passing expiry-forced check on a `human:` entry is NEVER re-dated or cleared by you either: it goes to § DEC-GATE as a human-attested expiry (`Keep / Re-date-as-sweep / Defer`). At Gather write only the candidates, to `gather.json`'s `human_expiries`; the Synthesize phase agent builds the list from them as the last step of § SYN-RECONCILE, after its re-raise scan, and only for a heading in `verified`, not returned in `stale_entries`, whose file is `checked`. A heading never enters it when it carries one of these other § DEC-GATE items that actually reaches the gate this sweep (a fresh detection § SYN-RECONCILE removed as already adjudicated does not count): a surfaced `stale_entries`, `subsumed_entries` or `governance_conflicts` item, a re-raised recorded adjudication, a duplicate-heading item, or a native-harvest near-duplicate item naming it as the existing entry. That list is closed. A promotion candidate is not on it: it yields to the gate and is not offered for promotion this sweep. A heading merged, renamed or removed this sweep, or named in a user-tier budget proposal, never enters it either. Pass the brief's `expiry` rule to the sub-agent unaltered. A `verified` item may carry a `method` only when that method was actually used. `stale_when_unknown` is NOT fired and forces nothing. NEVER summarize, shorten or re-word the brief, and never drop a rule from it to save context.
- **The harvest reads the side file only.** For a project without an `all tasks` agent (`sweep/dispatch.json`'s `harvest`), you, the Gather phase agent, write the items to `handoff/harvest.json`. Build `HARNESS_HARVEST:` signals only from `plans.accept_and_note`, quoting the item word for word. NEVER open a plan body the manifest did not extract, and NEVER read the whole governance corpus: grep, then read only the sections the hits fall in.
- **Check every collapsed checkpoint pair.** The per-project agent collapses; you only check what it returns. Name each collapsed pair in the Report beside the project's `checkpoint_collapsed` count. Never drop or merge a session yourself, and never count a dropped duplicate toward any `frequency`.
- **Count-verify and coverage are scripts.** After the last batch run `dream-sweep.py countverify` and `dream-sweep.py coverage`. `coverage` must report no label `missing`; it alone decides the stamp set. Build `handoff/gather.json` only then, with `dream-sweep.py gather` (never by hand), and run `handoff check gather.json`.
